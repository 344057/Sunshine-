# Sunshine个人工作站 · 超级管理员使用方案

> 本文以**当前项目代码与配置**为准（文档与代码不一致时，以代码为准）。
> 涉及文件：`js/data.js`、`js/config.js`、`js/api.js`、`js/app.js`、`js/cloud-config.js`、
> `server.js`，以及云端 `profiles` 表与其触发器配置。
> 最后更新：2026-11-19

---

## 0. 先明确三个概念（避免混淆）

| 概念 | 代码中的对应物 | 说明 |
|------|--------------|------|
| **超管** | 角色 `role = 'admin'` | 一个角色值，不是独立功能。顶栏显示「超级管理员」。 |
| **绑定 / 验证向导** | 5 步 `BIND_STEPS`（手机→短信→邮箱→邮件→完成） | 只完成账号身份核验，**不会**赋予管理员身份。 |
| **演示模式 / 云端模式** | `state.cloudMode` | 两套数据源：本地 `localStorage` 与云端数据库，身份互不通用。 |

一句话：**"绑定超管"实质是把某账号的角色字段设为 `admin`**；绑定向导与超管身份是两件事。

## 1. 超管身份的获得、切换与失效条件

### 1.1 获得（四条路径）

| 路径 | 模式 | 具体机制 | 代码/配置依据 |
|------|------|---------|--------------|
| **默认超管初始化** | 演示 | 首次初始化时自动创建 `admin / 123456`（`role:'admin'`）；配置入口 `APP_CONFIG.auth.superAdmin`，幂等且绝不覆盖已有账号 | `app.js` `ensureSuperAdmin()`；`config.js` `auth.superAdmin` |
| **内置超管账号直接登录** | 演示 | 内置用户 `u05 王校长 / principal@sunny.edu.cn`，`role:'admin'`，登录即超管 | `data.js` USERS 第 53 行 |
| **后台人员管理授权** | 演示 / 云端 | 管理后台 → 人员管理 → 新建/编辑 → 选择角色（含自定义角色）、部门 / 身份（含「学生家长」）、性别、年龄、个人签名、在线状态 → 保存（可一并设置初始密码）；云端写入 `personnel` 白名单并同步内部通讯录 | `app.js` `userFormModal()` / `saveUser()`；`api.js` `createPerson()` / `updatePerson()` / `syncDirectoryUsers()` |
| **云端邮箱自动提权** | 云端 | 指定邮箱 `3440576634@qq.com` 首次 OTP 登录时，`profiles` 表的 `BEFORE INSERT` 触发器 `trg_promote_designated_admin` 自动把 `role` 写成 `admin` | 云数据库触发器；`app.js` `cloudLoginSuccess()` 从 `profile.role` 读取 |

> 云端提权是**服务端触发器**，当前处于启用状态。`3440576634@qq.com` 已在 `profiles` 与 `personnel` 中登记为超管。公开注册接口 `registerUser()` 已移除，所有账户只能由超管在人员管理中创建——这是刻意的安全边界。

**默认超管初始化说明（演示模式）**：`ensureSuperAdmin()` 在启动时（hydrate + 接口绑定之后）执行，默认创建 `admin / 123456`，用户名/密码/显示名可在 `config.js` 的 `auth.superAdmin` 自定义。生效规则：
- **仅首次初始化生效**：标记 `superAdminInitialized` 写入 localStorage 后，后续启动不再创建、不修改任何账号。
- **不覆盖已有账号**：若已存在同名 / 同邮箱账号，只补写标记，用户名、角色、口令均保持原样（管理员改过的凭据不会被重置）。
- 想让新配置生效需清除本机站点数据回到首次初始化状态；正式使用请登录后立即改密。

### 1.2 角色与权限的来源（原「切换演示角色」已移除）

系统**不再提供「切换演示角色」入口**：`index.html` 中的菜单按钮、`app.js` 中的 `canSwitchToRole()` / `switchRole()` 及 `switch-role` / `do-switch-role` 事件均已删除。用户登录后角色由账号真实 `role` 决定，无法自行切换或提权。

超管通过「管理后台 → 角色权限」统一配置与分配：

| 子页签 | 能力 | 代码/配置依据 |
|--------|------|--------------|
| 角色权限分配 | 选择角色 → 勾选权限项 → 保存；保存后导航即时重建，权限立即生效 | `app.js` `renderAdminRoles()` / `save-role` 分支；`api.js` `saveRoleConfigs()` |
| 权限项维护 | 新增 / 编辑自定义权限项；内置权限项（7 项）不可删除 | `api.js` `savePermissionDefs()`；内置项定义于 `config.js` `builtinPermissions` |
| 视图访问控制 | 为每个主视图（学习资料 / 学习感悟 / 内部通讯录）指定门禁权限项，留空则不设门禁 | `api.js` `saveViewPerms()`；映射 `data.js` `DEFAULT_VIEW_PERMISSIONS` |

**未授权入口隐藏 + 访问拦截**：`renderNav()` 依据 `canView(view)` 过滤菜单；`navigate(view)` 在入口之外再做一次门禁校验（即使伪造 `data-view` 直达也会被拦截并回退）。`canView()` 读取 `state.viewPerms` 映射并用 `hasPerm()` 判定角色是否具备该权限项。管理后台视图固定仅 `role==='admin'` 可见，不参与门禁分配。

> 权限项与视图门禁持久化到云端 `app_config`（key 分别为 `permissions`、`view_perms`），本地模式存 `localStorage`。自定义角色（r_custom_*）的权限判断与侧栏提示均已做兼容，不会因角色名未内置而报错。

### 1.3 失效

| 情形 | 结果 | 依据 |
|------|------|------|
| 退出登录 | `state.role` 重置为 `student`，账户回到默认用户 | `app.js` `logout` 分支 |
| 云端退出 | 清除云端会话与登录态 | `cloudLogout()` |
| 超管被他人降级 | 仅能由超管在「人员管理」修改角色；降级后重新登录生效（演示模式即时重建导航） | `app.js` `save-role` / `saveUser` 分支 |
| 记住登录态恢复 | 仅当 `remember && authed && account.verified` 同时满足才恢复；`role` 从存储读回并限定在 student/teacher/admin | `hydrate()` 第 77–81 行 |
| 账户被禁用 | 登录时拒绝（口令校验返回 `ACCOUNT_DISABLED`） | `api.js` `verifyPassword()` |

## 2. 入口、角色级别与权限差异

### 2.1 角色权限矩阵（`data.js` ROLES / PERMISSIONS，共 7 项）

| 权限项 | 超管 admin | 教师 teacher | 学生 student | 家长 parent* |
|--------|:---:|:---:|:---:|:---:|
| 查看学习资料 `view_material` | ✓ | ✓ | ✓ | ✓ |
| 下载资料 `download` | ✓ | ✓ | ✓ | — |
| 发布资料 `publish` | ✓ | ✓ | — | — |
| 内部消息 `message` | ✓ | ✓ | ✓ | ✓ |
| 用户管理 `manage_user` | ✓ | — | — | — |
| 角色权限 `manage_role` | ✓ | — | — | — |
| 数据看板 `view_stats` | ✓ | ✓ | — | — |

\* **以代码为准的实现细节**：`state.role` 只取 `student / teacher / admin` 三值。家长账号登录后会被映射为 `student`（`loginSuccess()` 与 `cloudLoginSuccess()` 均如此），因此实际运行时按学生权限运作，`r_parent` 矩阵不会被当前逻辑命中。

### 2.2 管理后台入口的一个事实

导航显示条件为 `state.role === 'admin' || hasPerm('view_stats')`（`navItemsForRole()`），而**教师角色拥有 `view_stats` 权限**。因此按当前代码，**教师同样能看到并进入「管理后台」入口**；`navigate()` 的拦截条件也是 `!hasPerm('view_stats')`，不会拦教师。

- 这意味着：`view_stats` 是进入后台的门禁，而非"仅超管"。
- 若产品意图是"仅超管可进后台"，需要把门禁改为 `state.role === 'admin'`——这属于**待确认的策略项**，本文不擅自更改，如实标注。

### 2.3 普通用户 vs 管理员 vs 超管的差异小结

- **普通用户（学生/家长）**：只能浏览、下载资料，站内消息；无发布、无后台、无用户/角色管理。
- **教师**：额外可发布资料、看数据看板；因 `view_stats` 目前也能进入后台（见 2.2），但没有超管专属的"角色越高越能提权"能力。
- **超级管理员**：拥有全部 7 项权限；是唯一能通过角色切换获得/回切 `admin` 的角色；负责用户增删改禁用、角色权限矩阵配置、资料管理、实时监测。

## 3. 超管可访问的功能、数据范围与权限边界

### 3.1 功能范围

进入管理后台后有 5 个标签页（`renderAdmin()`）：

| 标签 | 内容 |
|------|------|
| **实时监测** | 今日活跃用户数、今日消息互动、今日感悟/点赞、当前在线；3 小时分段趋势柱状图；**每 5 秒自动刷新**（可手动刷新/开关，输入时暂停，离开页面停定时器） |
| **数据概括** | 账户总数、学习资料、今日活跃、消息互动统计卡；近 7 天趋势、角色构成与最近账户 |
| **用户管理** | 用户列表、新建/编辑/禁用启用/删除；角色下拉含「超级管理员」；可设置初始密码 |
| **资料管理** | 学习资料列表/搜索、新建、编辑、删除（走 `SunnyAPI` 资料 CRUD 接口） |
| **角色权限** | 选择角色、勾选/保存 7 项权限矩阵，保存后立即影响导航与发布权限 |

### 3.2 数据范围

- **演示模式**：`localStorage`（键 `sunny-classroom-web-v1`）中的 `users / roles / materials / shares / conversations / notifications / account` 全量可见可改。
- **云端模式**：`profiles / shares / share_likes`。行级安全（RLS）为——内容对所有登录用户**可读**，但**只能增改自己的数据**（`owner_id = auth.uid()`）；超管身份**不等于**绕过 RLS，超管在云端同样受行级隔离约束。

### 3.3 权限边界（必须清楚）

1. **前端权限仅用于展示与交互控制**，不是安全边界。角色判断、菜单隐藏、视图门禁（`canView()`）都能被浏览器端篡改。已移除演示角色切换入口，但真正的角色来源仍应以服务端会话为准。
2. 真正的安全边界在服务端：云端靠 RLS + `auth.uid()`；演示模式**没有服务端鉴权**。
3. 云端 `setPassword()` 只更新本地用户对象，**不会**修改云端认证服务的凭据——云端账号的身份验证始终由邮箱验证码（OTP）服务负责。
4. 超管不能通过前端"查看或导出他人密码"——口令即使设置也只以哈希形式存在本机（见第 6 节）。

## 4. 从登录到进入超管功能的主要操作流程

### 4.1 演示模式（最快体验）

```
登录页输入超管账号（默认 admin / 123456，或内置 principal@sunny.edu.cn）
   → 口令校验通过
   → 若首次登录（verified=false）→ 5 步绑定向导（验证码 123456）→ 验证完成
   → 进入平台，因账号 role=admin，左侧直接显示「管理后台」
   → 管理后台 → 角色权限：维护权限项、给角色分配、配置视图门禁
   → 管理后台 → 人员管理：创建人员并分配角色，人员用本人账号登录
```

> 只有当前已是超管，角色菜单才会列出「超级管理员」；普通账号看不到也切不过去。

### 4.2 云端模式（真实持久化）

```
登录页 → 输入账号（邮箱）+ 密码 → 登录
   → 系统按 owner_id 读取/创建 profiles
       · 指定超管邮箱 → 触发器写入 role='admin' → 以超管身份进入
       · 其他邮箱 → 默认 role='student'
   → 左侧「管理后台」（因 role=admin）→ 使用各管理功能
   → 学习感悟的发布/点赞/评论实时读写云端 shares / share_likes / share_comments

忘记密码：登录页 →「忘记密码？」→ 输入绑定邮箱 → 获取验证码（真实邮件）
   → 填入 6 位码 + 新密码 → 重置后用新密码登录（验证码仅用于身份核验，不作为登录方式）
```

> 云端登录必须使用正式 HTTPS 域名（在线链接），`localhost` 下云端能力不可用；OAuth Origin 校验要求域名与云端 endpoint 一致。

## 5. 关键限制、安全注意事项与审计要求

### 5.1 关键限制

- **演示级平台**：无服务端认证、无 HTTPS（本地）、数据多存于浏览器；**不得用于生产或存放真实个人信息**。
- **口令为演示级哈希**：`demo$盐$混淆值`，用于避免明文落盘，**不能抵御离线爆破**（见 6.1）。
- **超管提权硬编码在云端触发器**：邮箱写在数据库函数里，变更需改 SQL。
- **教师可进后台**（2.2），属于当前策略的真实行为。
- **自动刷新是运营监测，不是安全审计日志**——不留存"谁在何时改了什么"的不可抵赖记录。

### 5.2 安全注意事项

- 前端角色/权限判断一律可被绕过；生产必须服务端 RBAC + 服务端会话 + HTTPS。
- 修改角色权限矩阵、删除用户、删除资料均为高影响操作，操作前确认对象。
- 云端 RLS 是数据隔离的最后一道门，任何前端改造都不得破坏 `owner_id = auth.uid()` 策略。
- 口令修改入口应校验当前口令（已实现），防止他人趁会话未退改密。

### 5.3 必要的审计要求（当前缺口与建议）

当前系统**没有独立的审计日志表**，建议补强（本文只提出要求，未擅自实现）：

1. **关键操作留痕**：超管的用户角色变更、用户删除、角色权限改动、资料删除、密码重置，应记录 `操作者 owner_id / 动作 / 目标 / 时间 / IP`。
2. **登录审计**：记录登录成功/失败、验证码发送与校验、口令修改事件，失败次数异常可告警。
3. **不可篡改**：审计表仅允许 `INSERT`，禁止 `UPDATE/DELETE`（RLS 不开放写权限给前端）。
4. **定期复核**：核对 `profiles` 中 `role='admin'` 的账号清单（当前应仅指定超管邮箱），清理异常提权。
5. **最小权限**：除必要人员外，不授予 `admin`；演示环境的角色切换能力上线前必须移除或服务端化。

## 6. 新增需求实现说明与影响分析

本节说明本次纳入的两项需求：**增加密码设置项**、**邮箱验证仅首次登录必须完成**，以及它们对系统各环节的影响。

### 6.1 新增：密码设置项

**当前实现（改造后）**

- 配置（`js/config.js`）：新增 `APP_CONFIG.auth` = `{ defaultPassword:'123456', minLength:6, emailVerifyOnce:true }`。
- 接口层（`js/api.js`）：
  - `hashPassword()` / `verifyPasswordHash()` / `passwordMatches()`：演示级"盐 + 4 轮 FNV 混淆"，存储格式 `demo$盐$值1$值2`；**明文口令不落盘**。
  - `verifyPassword({userId,password})`：登录校验，返回统一结构；禁用账户返回 `ACCOUNT_DISABLED`。
  - `setPassword({userId,currentPassword,newPassword})`：校验当前口令 → 校验新口令长度与"不同于旧口令" → 写入新哈希。
  - 内置/历史账户无哈希时用默认口令 `123456` 兼容；超管创建人员时写入 `passwordHash`（可在编辑表单中重设）。
- 界面（`js/app.js`）：
  - 登录页密码框**不再预填**，placeholder 提示「初始密码 123456，可自行修改」。
  - 「账户安全与绑定」弹窗新增「修改登录密码」区：当前密码 + 新密码 + 确认新密码，调用 `setPassword`。
  - 修改密码前会提示先保存绑定信息，避免用户误以为密码随绑定一起保存。

**需要调整的配置/逻辑与影响**

| 维度 | 影响 |
|------|------|
| **登录流程** | 从"输入任意邮箱+密码即登录"变为"白名单 + 口令真实校验"：仅超管创建的人员可登录，内置账户用初始 `123456`，新账户用超管设定的初始口令，错误密码被拒绝。 |
| **身份验证** | 演示模式从"无验证"升级为"本地哈希口令"；但仍非生产安全（见 5.1）。云端模式仍是 OTP，口令设置项不改变云端认证方式。 |
| **权限控制** | **无变化**。口令属于身份认证，角色/权限由 `role` 与权限矩阵决定，两者解耦。 |
| **用户提示** | 登录页、账户安全弹窗文案均已更新，说明初始口令、修改入口与"仅首次验证"；登录页明确提示账号由超管统一创建。 |

> 生产化建议：把 `hashPassword`/`verifyPassword` 换成服务端 bcrypt/argon2 + 会话令牌，前端不再持有任何口令哈希。

### 6.2 调整：邮箱验证仅首次登录必须完成

**当前实现（改造后）**

- 逻辑（`app.js` `handleLogin()`）：`APP_CONFIG.auth.emailVerifyOnce !== false` 且 `verified === false` 才进入绑定向导；验证通过后 `verified=true` 并写入 `emailVerifiedAt` 时间戳，持久化到 `localStorage`。后续同账户登录直接放行，**不再重复验证**。配置设为 `false` 时不强制验证，管理员分配的账号凭口令即可用。
- 接口（`api.js` `markEmailVerified()`）：绑定向导最后一步调用它统一写入 `verified` 与 `emailVerifiedAt`（本地先行落盘），并同步当前会话工作副本与会话快照；云端双写 `profiles` / `personnel` 的 `email_verified`（RLS 允许则成功），返回 `cloudSynced` 供上层提示。
- 超管创建人员（`createPerson()`）：默认 `verified:false`，可传 `verified:true` 创建即验证；`personToRow` 写入云端 `email_verified`。后台新建/编辑表单提供「验证状态」下拉，超管可随时修正或撤销。
- 云端：`personFromRow` 从 `email_verified` 回读 `verified` 与 `emailVerifiedAt`，`publicUser` 双向携带，云端重载 / 切换账户后状态不丢失。云端账户的身份验证走账号密码（邮箱验证码仅用于忘记密码）。

**需要调整的配置/逻辑与影响**

| 维度 | 影响 |
|------|------|
| **登录流程** | 首次登录多一步 5 步验证向导（验证码演示值 `123456`）；此后登录直达平台，流程缩短。 |

## 7. 常见异常排查

| 现象 | 可能原因 | 排查/处理 |
|------|---------|-----------|
| 提示"密码错误" | 内置账户初始口令为 `123456`；或用户已改过密码 | 用初始口令试；仍忘记密码则点击登录页「忘记密码？」通过邮箱验证码重置后登录。 |

| 修改密码提示"当前口令不正确" | 当前口令输错 | 内置账户用 `123456`；自己改过的用最后一次设置的口令。 |
| 提示"请先保存绑定" | 改了邮箱/手机但未保存就点了改密码 | 先点「保存绑定」，再修改密码。 |

### 9.9 账户验证状态的排查与修复

**问题**：新建账户的验证状态「不可用」——账户反复进入绑定向导、后台显示未验证且无法修正。

**根因**（生成 / 存储 / 传递 / 展示四环断点）：
1. 生成：云端 `personToRow` 未写 `email_verified`，新建账户该列恒为 NULL；
2. 存储：`markEmailVerified` 只改本地 `localStorage`，云端不落库；
3. 传递：`personFromRow` 依赖 `email_verified` 回读，字段从未正确写入 → 云端重载后状态回退为未验证；
4. 展示/编辑：后台表单无验证状态字段，`updatePerson` 不接受 `verified`，超管无法修正。

**修复**：`personToRow`/`personFromRow` 双向映射 `email_verified`；`markEmailVerified` 本地先行 + 云端双写 `profiles`/`personnel` 并同步当前会话快照；`createPerson`/`updatePerson` 支持 `verified`（默认未验证，可指定已验证）；后台新建/编辑表单新增「验证状态」下拉；`emailVerifyOnce` 配置真正生效（默认强制首次验证）。云端表 `email_verified` 字段已存在，无需迁移。

**验证步骤**：
1. `npm test` 82 项全通过，重点看 5 项验证状态用例；
2. 后台新建账户选「未验证」→ 该用户登录应进入绑定向导；
3. 完成向导后刷新页面 / 换标签 → 不应再进入向导，账户安全弹窗显示验证日期；
4. 后台将该账户编辑为「已验证 / 未验证」→ 列表列与登录行为应即时反映；
5. 云端模式：超管新建账户指定已验证 → 其他设备登录后人员列表与自身状态均为已验证。

### 9.7 在线状态同步规则

在线状态 `presence` 取 `online / away / offline`，可在后台人员新建/编辑表单中设置，保存到本地用户表与云端 `personnel.presence` 列，并随人员变更同步到通讯录。全站按同一口径判定（由 `api.js` `effectivePresence()` 统一）：

1. 停用账户（`status=disabled`）强制显示离线；

### 9.8 多账户同时在线与会话管理

## 10. 账户清理：仅保留 admin

**入口**：管理后台 → 人员管理 → 底部「危险操作 · 账户清理」。该操作不可撤销，请在清空前确认无需保留任何非 admin 账户的数据。

### 10.1 执行前校验

- 调用者必须是超级管理员（接口层 `requireAdmin()` 二次校验，非超管返回 `FORBIDDEN`）。
- 受保护账户按 `js/config.js` → `auth.accountCleanup` 的优先级识别：
  1. `protectedEmail`（默认 `3440576634@qq.com`）对应的启用超管；
  2. `protectedUsername`（默认 `admin`）对应的启用超管；
  3. 当前登录的启用超管。
- 若未找到候选、候选之间存在冲突、账户不是 `admin` 角色 / 已禁用，或当前登录者不是该账户，预检直接终止，不执行任何删除。
- 预检只读，返回受保护账户、待删账户、逐账户关联数据量和汇总数量。

### 10.2 二次确认

- 第一步：查看「影响范围」弹窗，核对保留账户与待删账户清单。
- 第二步：勾选「我已核对」并输入确认短语（默认 `仅保留ADMIN`），按钮在此之前保持禁用。接口层同时校验 `confirm === true` 与短语完全一致，缺少任一项返回 `CONFIRMATION_REQUIRED`。

### 10.3 清理范围与保护

| 数据 | 处理方式 |
|------|----------|
| `personnel` / 本地用户 | 删除非 admin 账户；最终仅保留 admin |
| `profiles` / 本地账户资料 | 按账户身份键删除 |
| `shares` | 删除这些账户发布的感悟 |
| `share_likes` / `like_by` | 删除这些账户的点赞记录，并从他人感悟中移除其点赞引用 |
| `materials` | 删除这些账户发布的资料（公共种子资料无 owner，不受影响） |
| 站内会话 | 删除与这些账户相关的会话及其消息 |

保护机制：清理目标按稳定标识（id / owner_id / uid / email）匹配，不使用显示名；所有目标身份键都会先剔除 admin 身份键，任何删除路径都不会命中 admin。账户表中已不存在、但仍出现在关联数据里的旧 `owner_id`（孤儿身份）也会被纳入清理，避免残留无账户却仍占有数据的身份。云端逐项失败会写入失败项并继续处理其余账户，最后复核 admin 仍存在且为启用超管。

### 10.4 返回结果

清理完成后弹窗展示：**清理数量**（账户、人员、资料、感悟、点赞、会话等）、**已删除账户**、**失败项**（若有）和**最终账户状态列表**。接口返回结构为 `{ ok, data: { deletedAccounts, deletedIdentities, counts, failedItems, finalAccounts, keep }, error, message }`。

### 10.5 云端边界

- 已为云端数据库增加 `profiles_delete_admin`、`shares_delete_admin`、`share_likes_delete_admin`、`shares_update_admin` 策略，允许超管清理他人关联数据；`personnel` / `materials` 原有超管写策略保持不变。
- 云端认证账户（登录身份记录）不在本接口删除范围内。账户移出 `personnel` 白名单后，即使认证身份仍存在也无法登录系统；如需彻底注销认证身份，须在身份服务侧另行处理。

- 手机端通讯录「发消息」改为独立全屏聊天界面，顶部含返回、对方信息、语音通话、视频通话按钮；电脑端保持左右分栏。
- 新增语音通话与视频通话：真实摄像头/麦克风采集、点对点连接、来电弹窗（接听/拒绝）、通话计时、麦克风/摄像头开关、挂断。
- 新增云表 `call_signals` 及 RLS 策略（全员可读、仅本人可增删）。

### 11.2 两种通话模式（自动判定）

| 模式 | 触发条件 | 行为 |
|------|----------|------|
| 真实模式 | 云端登录有效 + HTTPS + 浏览器支持 getUserMedia/RTCPeerConnection | 真实采集音视频，经云表交换 SDP/ICE，公共 STUN 打洞，建立点对点连接 |
| 演示模式 | 本地演示登录 / 非 HTTPS / 无设备权限 / 连接失败 | 同浏览器 localStorage 信令走完整来电→接听→挂断流程，控件可用，但不传输真实音视频 |

界面顶部会标注当前是「加密通话」还是「演示模式」，避免误解。

### 11.3 通话操作

- 发起：在聊天界面（手机全屏 / 电脑分栏）点击顶部电话图标发起语音、摄像头图标发起视频。
- 来电：被叫方弹出微信式来电卡片（头像 + 邀请类型 + 拒绝/接听），45 秒无应答自动结束。
- 通话中：麦克风按钮实时静音/取消（`getAudioTracks().enabled`），摄像头按钮实时关闭/开启（`getVideoTracks().enabled`），视频模式显示本地小窗；挂断按钮结束并释放媒体流与连接。
- 清理：挂断结束通话计时、轮询、RTC 连接、本地轨道，并向对方发送 hangup 信令。

### 11.4 边界与注意事项

- 真实通话要求双方不同设备/浏览器、各自登录云端账号、授予设备权限、网络允许 P2P；对称 NAT 等复杂网络可能失败并降级为演示模式。
- 同一浏览器需用不同标签分别登录不同账户才能用演示模式双端体验；单设备摄像头通常只被一个标签占用，第二个标签会退化为纯界面演示。
- 通话信令为临时数据：`call_signals` 表内容仅为一次通话的协商消息，通话结束后无自动清理策略，可按需由管理员定期删除历史记录（不影响功能）。
- 无服务端 TURN 中继，纯前端方案不保证所有网络下都能建立真实连接；生产级通话建议接入 TURN 服务与服务端信令。

## 12. 消息通知发布（全员广播）

### 12.1 权限
新增内置权限项「发布消息通知」（`publish_notice`）。超级管理员默认具备；如需让校长等角色也能发布，进入「角色权限」选择对应角色勾选该权限并保存。具备该权限的角色在侧栏会看到独立的「消息通知」界面，其他成员看不到发布入口、但仍会在顶栏铃铛收到通知。

### 12.2 发布与送达
- 在「消息通知」界面填写标题、类型（通知/公告/提醒）、正文，可选置顶，点击「发布给全体成员」。
- 通知写入云端 `notices` 表；所有账户约每 12 秒轮询一次，新通知自动出现在顶栏铃铛；本地演示模式用 localStorage 跨标签即时同步。
- 已读回执记录在 `read_by` 字段，发布者可查看发布历史并删除。
- 云端 `notices` 表 RLS：全员可读，发布/删除需为作者本人或平台管理员；角色级发布权限在应用层二次校验。

## 13. 上线活动通知记录

通话结束（已接通记时长、未接/拒接记未接来电）与「收到消息但用户不在该会话」时，会生成活动事件写入当前账户会话私有的待投递队列。用户上线（登录 / 切换账户）时，这些事件以系统记录条形式补记进对应联系人的聊天记录；若当前在线则即时落入。各账户会话隔离，互不干扰。这样上线即可看到离线期间错过的电话、消息与视频通话。

## 14. 数据备份与还原（仅超管）

### 14.1 入口
「管理后台 → 备份管理」，仅超级管理员可见。

### 14.2 三种备份目标（可多选，一次生成同一份快照）
- **系统内部**：存到浏览器 localStorage 的独立键，保留最近 20 份，可在「备份记录」中下载或还原。
- **NAS（WebDAV）**：填写 NAS 的 WebDAV 地址、账号、密码、远程目录，上传采用 WebDAV `PUT`。要求 NAS 开启 WebDAV 且允许跨域（CORS）；若上传失败会自动改为下载备份文件，可手动存入 NAS。
- **本地电脑**：直接下载带时间戳的 JSON 备份文件。

### 14.3 定时自动备份
可设置启用与间隔（1–720 小时），页面保持打开时按间隔自动备份到系统内部。浏览器页面关闭后定时器不运行，此期间不会自动备份——如需真正的后台定时，应部署常驻服务端任务。

### 14.4 还原
可从内部备份记录点击「还原」，或选择本地 JSON 文件还原。系统会校验备份文件格式与版本，二次确认后覆盖本地数据并重新加载。**还原会覆盖当前数据，操作前请先备份现有数据。**

### 14.5 边界
- 备份数据保存在浏览器侧（localStorage / 用户设备 / 用户 NAS），不含服务端副本；清除浏览器数据会导致内部备份丢失，重要数据请下载或存 NAS。
- WebDAV 账号密码仅保存在本浏览器本地配置中，不会上传到云端。

## 15. 聊天图片与表情包（管理员须知）

- 聊天输入区新增微信式「＋」折叠面板：照片（本地文件 / 手机相册）、拍照（手机后置摄像头）、以及为后续功能预留的「更多」入口。
- 图片经浏览器本地压缩后以 dataURL 存入会话记录，点击缩略图可放大预览；自定义表情包与收藏同样按账户隔离保存。
- **存储提醒**：图片与表情包数据保存在浏览器 localStorage 中，不占云端配额，但会占用本机存储空间。单张图片自动压缩（最长边 1280px、JPEG 质量 0.72），自定义表情上限 60 个；如需释放空间，可在浏览器中清理对应站点数据（注意会同时清除其它本地数据）。
- 表情面板内置 6 类常用 emoji，支持自定义添加 / 收藏 / 删除；这些都是用户个人数据，管理员无法跨账户查看。

## 16. 闲置超时二次验证（30 分钟）

- 用户（含超管）登录后 **30 分钟无操作**会自动锁定并弹出二次验证层，只需重新输入当前账户密码即可继续，不丢失任何数据。鼠标 / 键盘 / 触摸 / 滚动都会刷新计时。
- 超时时长可在 `js/config.js` 的 `auth.idleTimeoutMinutes` 调整（单位分钟，默认 30）。
- 二次验证仅校验当前账户密码，不走注册 / 绑定向导，也不重置多账户会话。

## 17. 跨设备同步（手机 / 电脑一致）

- 云端登录后，手机与电脑的数据通过 `user_sync` 表在三个域自动对齐：
  1. **workspace**：筛选、已添加学习、会话消息、通知、表情等私有工作区；
  2. **account**：账户资料、角色、权限矩阵与视图门禁；
  3. **schedule**：课程表。
- 本地变更节流上传，启动与定时轮询拉取，`updatedAt` 较新的一方胜出；拉取后只落本地不回推，避免周期震荡。
- **管理要点**：在电脑端后台分配的角色 / 权限 / 发布的通知 / 配置的课程表，手机端登录同一云端账户后会自动一致，无需重复设置。首次云端登录会立即对齐一次。

## 18. 课程表与班级主任

### 18.1 角色与授权
- 新增内置角色「**班级主任**」（`r_headteacher`），自带 `manage_schedule` 权限。
- 超管在「管理后台 → 人员管理 → 新建/编辑账户」中选择「班级主任」角色，并在「**管理班级**」多选框中勾选其负责班级（1–6 年级 × 1–3 班，可多选，**一人可同时管理多个班级**）。
- 权限边界：**超管**可编辑全部班级；**班级主任**仅能编辑自己管理的班级；其他角色只读。

### 18.2 配置课程表
- 侧栏「课程表」进入，顶部切换班级；表格展示周一至周五 × 第 1–7 节的课程、上课时间、当科老师、备注。
- 有编辑权限时点击任意节次可增删改（当科老师从现有教师/主任账户中选择）；「套用模板」按国内小学通用作息补齐未设置节次，不覆盖已有课程。
- 内置模板参考周边学校常见作息（08:00–16:20、每节约 40 分钟、上午 4 节 + 下午 3 节），科目按年级配比；可按本校实际逐节调整。
- **打印 / 导出 PDF**：课程表右上角「打印 / PDF」按钮，所有可查看者都能用。点击后生成一页 A4 横向打印页（含班级、打印日期、每周 5 天 × 7 节完整课程、老师与备注），在浏览器打印对话框里选择目标打印机直接打印，或选「另存为 PDF」导出文件。无数据时会自动按内置模板打印。

### 18.3 云端与本地边界
- 云端登录：课程表节次存于 `class_schedules` 表，全员可读，写权限由 RLS `can_manage_class` 按 `personnel.managed_classes` 校验（与前端双重校验）。
- 本地演示：改动仅保存在当前浏览器，不跨设备；如需跨设备请使用云端登录。

### 18.4 数据表变更
- `personnel` 新增 `managed_classes` 列（JSON 数组文本）。
- 新建 `user_sync`（跨设备同步）与 `class_schedules`（课程表）两表，均已开启 RLS 并授权 `authenticated, anon`。
