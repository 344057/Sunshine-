# Sunshine个人工作站 Web · 部署教程

一个面向 1–6 年级的学习平台。提供两种运行模式：

- **演示模式**：纯本地静态站点，数据保存在浏览器 `localStorage`，零依赖、开箱即用，无需联网。
- **云端模式**：接入 WorkBuddy 云服务，使用账号密码登录，学习感悟保存到云端 PostgreSQL 数据库（含行级安全隔离），可跨设备同步。邮箱验证码仅用于「忘记密码」流程验证身份、重置密码。

### 云端数据表（已在云服务环境创建）

| 表 | 用途 | RLS 策略 |
|---|---|---|
| `profiles` | 用户资料（昵称/年级/角色） | 登录用户可读，仅本人可增改 |
| `shares` | 学习感悟 | 登录用户可读，仅作者可增删改 |
| `share_likes` | 点赞记录（防重复） | 登录用户可读，仅本人可增删 |
| `share_comments` | 感悟评论（学生/老师/小组三类） | 登录用户可读，仅作者可增删改，管理员可管理 |

| `personnel` | 自定义人员白名单 | 全员可读，仅管理员可增删改 |
| `app_config` | 角色权限/视图门禁配置 | 全员可读，仅管理员可写 |
| `call_signals` | 内部通话信令（invite/accept/hangup/offer/answer/ice） | 全员可读（按 call_id + 收发双方前端过滤），仅本人可增删 |
| `notices` | 全员广播消息通知 | 全员可读，具备 `publish_notice` 权限的角色可发布/删除（应用层校验 + RLS owner/管理员） |
| `user_sync` | 跨设备同步（workspace 工作区 / account 资料权限 / schedule 课程表三域） | 仅本人与管理员可读可写（owner_id = auth.uid()） |
| `class_schedules` | 课程表节次（班级/星期/节次/课程/教师/备注） | 全员可读；仅超管或对应班级的班级主任可增删改（`can_manage_class`） |

`personnel` 表新增 `managed_classes` 列（JSON 数组文本），用于保存班级主任可管理的班级清单；`can_manage_class(class_key)` 数据库函数据此判断课程表写权限。

云端客户端初始化、账号密码登录与忘记密码、感悟读写分别位于 `js/cloud-config.js`、`js/app.js` 的 `renderForgotPassword` / `submitShare` / `submitComment` / `toggleLike`。应用标识与域名在 `.wbapp_*.genie`（工作区根目录）中登记，发布时复用同一 `applicationId` 以保持云端 Origin 一致。

### 内部通话（语音 / 视频）与手机端聊天

- **手机端独立聊天界面**：手机（视口宽度 ≤ 680px）在通讯录点击「发消息」会进入全屏聊天页（顶部返回 + 对方信息 + 语音/视频通话按钮 + 消息区 + 输入区），电脑端仍为通讯录左右分栏。离开通讯录自动收起全屏聊天。
- **语音 / 视频通话入口**：聊天界面顶部电话 / 摄像头图标，或在成员列表发起。
- **真实模式**：满足「云端登录有效 + HTTPS 安全上下文 + 浏览器支持 getUserMedia/RTCPeerConnection」时，用真实摄像头/麦克风采集，通过 `call_signals` 云表交换 SDP/ICE 信令，公共 STUN 服务器打洞建立点对点连接。支持来电弹窗（接听/拒绝）、通话计时、麦克风/摄像头实时开关（`track.enabled`）、挂断清理。
- **演示降级模式**：本地演示登录、非 HTTPS、无摄像头权限或真实连接失败时自动降级——使用同一浏览器的 localStorage 信令走完整「来电→接听/拒绝→挂断」流程，界面与真实模式一致，但不传输真实音视频（通话界面顶部明确标注「演示模式」）。
- **使用前提（真实通话）**：双方使用不同设备/浏览器、各自登录云端账号、均授予摄像头/麦克风权限、网络环境允许 P2P（对称 NAT 等复杂网络可能失败并降级为演示）。因 WebRTC 需要双方同时在线，暂无离线留言式通话。

通话信令工具的纯函数在 `js/api.js`（`newCallId` / `normalizeCallSignal` / `signalsFor` / `canStartCall` / `callMode` / `formatCallDuration`），WebRTC 连接与 UI 在 `js/app.js` 的「模块三点五」。

### 聊天图片与表情包（微信式加号面板）

- **加号折叠面板**：聊天输入区左侧「＋」按钮，点开是微信式工具格：**照片**（从电脑本地 / 手机相册选图）、**拍照**（调用后置摄像头）、以及「更多」预留位（后期新增接口只需在面板追加一项）。再次点「＋」收起。文件选择器由 `openImagePicker(useCamera)` **动态创建并挂载到 body 的临时 input**，在用户点击的同步栈内 `.click()` 唤起（适配 iOS / 微信内置浏览器）；不使用聊天区内的静态隐藏 input，以避免桌面与手机全屏同时存在同 id 输入导致串台、以及聊天区重绘后 change 监听丢失。拍照模式设置 `capture="environment"`，相册模式不设置；临时输入在选图后或下次打开前清理。
- **图片压缩与发送**：选图/拍照后经 canvas 等比缩放（最长边 1280px）+ JPEG 质量压缩为 dataURL，再作为图片消息发送；过大图片自动二次降质。聊天记录中显示缩略图，点击可打开大图预览。图片消息会占用浏览器存储空间，请控制数量。
- **emoji 表情面板**：输入框左侧笑脸按钮展开，内置微信常用 emoji（表情 / 手势 / 爱心 / 自然 / 食物 / 符号 6 类），点击插入输入框；支持回车发送。
- **自定义表情包**：在表情面板「自定义」分类点「添加表情」，填名称并通过可见的文件输入选择图片（自动压缩为 dataURL，选后可预览）；「管理」里可删除、收藏。「收藏」分类汇总已收藏的 emoji 与自定义表情。自定义表情点击后作为大表情消息发送。
- **会话隔离**：图片消息存于会话的 `conversations`，自定义表情与收藏存于会话的 `emoticons`，均按账户隔离（纳入 `WORKSPACE_KEYS`）。

相关纯函数在 `js/api.js`（`fitImageSize` / `dataUrlBytes` / `normalizeImageMessage` / `normalizeSticker` / `normalizeEmoticons` / `toggleFavorite` / `EMOJI_GROUPS`），面板与发送逻辑在 `js/app.js`（`chatComposeHTML` / `chatMorePanelHTML` / `chatEmojiPanelHTML` / `compressImageFile` / `pushImageMessage`）。

### 消息通知中心（全员广播）

- **独立界面**：侧栏「消息通知」是一个单独操作界面；发布入口由 `publish_notice` 权限项门禁——超管默认具备；如需让「校长」等角色也能发布，在「管理后台 → 角色权限」给对应角色勾选「发布消息通知」即可。
- **全员送达**：发布后写入云端 `notices` 表，所有登录账户定期轮询拉取（约 12 秒）并在顶栏铃铛显示；本地演示模式通过 localStorage 跨标签即时同步。
- **功能**：标题 / 类型（通知/公告/提醒）/ 接收范围 / 正文 / 置顶、已读回执（`read_by`）、发布历史与删除。所有成员可读，仅具备权限者可发布与删除。
- 纯函数在 `js/api.js`（`normalizeNotice` / `sortNotices` / `markNoticeRead` / `canPublishNotice`），界面与收发逻辑在 `js/app.js`「模块三点六」。

### 上线活动通知记录（未接来电 / 消息 / 视频通话）

- 通话结束（已接通记时长、未接/拒接记为未接来电）与「收到消息但当前未在该会话」时，会生成一条活动事件写入当前账户会话私有的 `pendingEvents` 队列。
- 用户上线（登录 / 切换账户）时，事件以居中系统记录条的形式补记进对应联系人的聊天记录（会话隔离，各账户互不干扰）；若当前已在线则即时落入。
- 纯函数在 `js/api.js`（`normalizeActivityEvent` / `activityToMessage` / `flushActivityEvents`），逻辑在 `js/app.js`「上线活动通知记录」小节。

### 数据备份与还原（超管专属）

- **入口**：管理后台 →「备份管理」标签，仅超级管理员可见。
- **三种备份目标（可多选）**：系统内部（浏览器 localStorage，保留最近 20 份）、NAS（WebDAV `PUT` 上传，需 NAS 开启并允许跨域）、本地电脑（下载 JSON 文件，文件名含时间戳）。
- **定时自动备份**：可设置间隔（1–720 小时），页面保持打开时按间隔自动备份到系统内部；关闭页面期间不执行。
- **还原**：可从内部备份记录或本地 JSON 文件还原，还原前二次确认，`validateBackup` 校验文件结构后覆盖本地数据并重载。还原会覆盖当前数据，操作前建议先备份。
- 纯函数在 `js/api.js`（`buildBackup` / `validateBackup` / `normalizeWebDavConfig` / `formatBackupSize`），界面与上传/下载/还原在 `js/app.js`「模块三点七」。

### 多账户登录入口

顶栏「账户 N」按钮（带文字与常显的在线账户数）即多账户入口：点击可查看所有在线账户、切换、登录其他账户、退出全部；手机端保留图标 + 数字角标。

## 四、配置端口与访问地址

服务器通过环境变量读取配置，默认监听 `127.0.0.1:5173`。

### 修改端口

```bash
# macOS / Linux / Git Bash
PORT=5174 npm start

# Windows PowerShell
$env:PORT=5174; npm start

# Windows CMD
set PORT=5174 && npm start
```

若端口被占用，终端会提示：

```
端口 5173 已被占用，请设置 PORT 环境变量后重试，例如：PORT=5174 npm start
```

### 允许局域网其他设备访问

默认只监听本机 `127.0.0.1`。如需手机 / 同事电脑访问，把 `HOST` 设为 `0.0.0.0`：

```bash
# macOS / Linux / Git Bash
HOST=0.0.0.0 PORT=5173 npm start

# Windows PowerShell
$env:HOST="0.0.0.0"; $env:PORT=5173; npm start
```

启动后，其他设备在同一局域网内访问 `http://<你的电脑IP>:5173`（可用 `ipconfig` / `ifconfig` 查看 IP）。

> 提示：放行防火墙时仅开放该端口，且演示环境不建议在公网长期暴露。

## 五、两种登录模式与功能导览

### A. 账号密码登录（推荐，真实持久化）

1. 在登录页输入超级管理员已创建并启用的**账号（邮箱）+ 密码**登录（内置账号初始密码 `123456`）。**系统不开放自助注册，未开通的账号会被拒绝**，账号由超管在「管理后台 — 人员管理」中创建并分配角色与初始密码。
2. **忘记密码**：点击登录页「**忘记密码？**」→ 输入绑定邮箱 → 点「获取验证码」→ 查收邮件填入 6 位验证码 → 设置新密码 → 用新密码登录。邮箱验证码**仅用于忘记密码时的身份验证**，不再作为登录方式。云端账户走云服务重置接口，本地账户使用演示验证码 `123456`。
3. 登录后「学习感悟」的发布、点赞与评论会实时读写云端数据库，**换设备、换浏览器登录同一账号即可看到相同数据**。
4. **会话有效期内（默认 7 天）无需重复登录**：刷新页面、打开新链接或新标签页都会自动恢复当前账户；同一浏览器不同标签页可各自登录不同账户、互不覆盖，可在顶栏「切换账户」面板中按需切换。

> 云端能力依赖发布域名完成 Origin 校验，请通过线上地址访问使用；本地 `localhost` 下云端数据同步不可用，但演示模式正常。

### B. 演示登录（本地，快速体验）

- 登录页使用**超级管理员创建的人员账号 + 密码**登录（内置账号初始密码 `123456`），数据仅存于当前浏览器。系统不再支持任意邮箱自动建号。
- 已完成验证的账号（如 `xiaoman@sunny.edu.cn`）直接进入平台。
- 未完成验证的账号会进入**5 步绑定向导**（手机号 → 短信验证 → 邮箱 → 邮件验证 → 完成），验证码统一为 `123456`。是否强制验证由 `APP_CONFIG.auth.emailVerifyOnce` 控制：`true`（默认）仅首次必须，`false` 则管理员分配的账号凭口令即可直接用。
- 验证状态（`verified` + `emailVerifiedAt`）是账号的持久属性：本地存 `localStorage`，云端存 `personnel.email_verified` / `profiles.email_verified`，刷新或换设备不会回退为「未验证」。超管也可在「管理后台 — 人员管理」的新建/编辑表单中直接指定验证状态。
- 勾选「记住登录状态」后，刷新页面会保留登录态；退出登录会清除。

### 默认超级管理员初始化

系统首次初始化（或尚未显式配置）时会自动创建一个默认超管账号，方便开箱即用：

- **默认用户名**：`admin`（也可用邮箱 `admin@sunny.edu.cn` 登录）
- **默认密码**：`123456`
- **角色**：超级管理员（可进入管理后台、人员管理、角色权限）

配置入口在 `js/config.js` → `auth.superAdmin`，可自定义默认值：

```js
superAdmin: {
  username: 'admin',     // 默认登录用户名
  password: '123456',    // 默认初始密码（留空回退到 auth.defaultPassword）
  displayName: '超级管理员', // 显示名称
},
```

**生效规则（幂等、不覆盖）**：
- 仅在**首次初始化**生效：一旦写入初始化标记（`superAdminInitialized`，随数据存于 localStorage），后续启动不再创建、不再修改。
- 若已存在同名 / 同邮箱账号（例如管理员已改过用户名或密码），只补写初始化标记，**绝不覆盖**已有账号的用户名、角色与口令。
- 修改配置后若要让新默认值生效，需先清除本机站点数据（localStorage）再刷新，使系统回到"首次初始化"状态。
- 默认凭据仅用于演示环境；正式使用请登录后立即在「账户安全与绑定」中修改密码。

实现位置：`js/app.js` 的 `ensureSuperAdmin()`（启动时在 `hydrate()` / `bindApiContext()` 之后调用）。

### 权限与角色（超管统一配置）

系统**已移除「演示角色切换」**：普通用户登录后的角色与权限完全由账号所属角色决定，用户无法自行切换身份或提权。

- **权限由超管分配**：超管在「管理后台 → 角色权限」中维护权限项、给角色勾选权限，并可配置每个主视图的门禁权限。
- **未授权入口隐藏 + 访问拦截**：普通用户只能看到已授权的功能入口；即使绕过菜单直接访问（伪造 `data-view`），也会被 view-level 门禁拦截并回退到有权限的页面。
- **即时生效**：权限分配保存后立即重建导航；云端账号下次登录会自动加载最新权限配置。
- **管理后台固定由超管独占**，不参与权限项分配。
- **发布资料**等操作按钮同样受 `publish` 权限控制（未授权则不显示）。

「角色权限」页分三个子页签：
1. **角色权限分配**：选择角色 → 勾选权限项 → 保存。
2. **权限项维护**：新增 / 编辑自定义权限项；内置权限项不可删除。
3. **视图访问控制**：为每个主视图（学习资料 / 学习感悟 / 内部通讯录）指定所需权限项，留空则不设门禁。

### 学生年级权限隔离

- **按年级分类展示**：学生登录后，学习资料与学习感悟只展示**本人所在年级**的内容；无年级的通用内容始终可见。资料筛选条的年级选项也只列出有权限的年级。
- **按年级限制操作**：发布感悟时只能选择有权限的年级（表单下拉已过滤，接口层 `assertGradeAccess` 二次校验）；评论也只能针对有权限年级的感悟，越权写入被拦截。
- **授权扩展**：管理员 / 教师 / 家长默认可访问全部年级；如需让学生跨年级学习，可在账户上设置 `allowedGrades`（年级数组）或 `gradeScope: 'all'`（全部年级）。
- 相关接口：`gradeScopeFor` / `canAccessGrade` / `filterByGradeScope` / `assertGradeAccess`。

### 学习感悟评论

- 每条感悟的评论按身份分为**学生评论 / 老师评论 / 小组评论**三类，分组展示并显示各类数量。
- 发表身份由角色决定：学生可发「学生评论 / 小组评论」，教师可发「老师评论 / 小组评论」，家长仅「小组评论」，管理员可发全部三类；无权使用的身份不会出现在下拉框中，接口层 `canPostComment` 兜底拦截。

- 相关接口：`COMMENT_KINDS` / `COMMENT_LABELS` / `commentKindsFor` / `canPostComment` / `normalizeComment` / `appendComment` / `groupComments`。

### 管理后台：实时监测

超管进入管理后台 → 「实时监测」，可视化查看：

- **今日活跃用户数 / 今日消息互动 / 今日感悟与点赞 / 当前在线用户** 四项核心指标（含环比趋势）。
- **实时变化趋势**：按 3 小时分段的活跃用户与消息互动柱状图。
- **自动刷新**：默认每 5 秒自动刷新（用户正在输入时自动跳过以免打断），可手动「刷新」或切换「自动刷新：开/关」。离开该标签或视图时定时器自动停止。

数据基于本地演示会话（账户状态 + 站内消息 + 感悟互动）实时计算；云端模式下感悟互动来自云端同步数据。

### 管理后台：数据概括

超管进入管理后台 → 「数据概括」，汇总展示：

- **统计卡**：账户总数、学习资料、今日活跃、消息互动。数值均来自当前已加载数据，不再使用固定示例值。
- **学习活跃趋势**：按最近 7 个自然日统计内容发布与消息互动；无带日期记录时显示正式空状态。

- **最近加入账户**：按创建时间倒序展示最多 5 条，并提供「查看全部」进入人员管理。
- **刷新与状态**：进入页签时云端模式会刷新人员 / 资料 / 感悟数据源，页面提供「刷新」按钮；加载中、无数据、计算异常均有明确提示，异常时可一键重试。

### 账户验证状态（生成 / 存储 / 传递 / 展示）

验证状态是账号的持久属性，统一用 `verified`（布尔）+ `emailVerifiedAt`（ISO 时间戳）表示，云端对应 `personnel.email_verified` / `profiles.email_verified`（timestamptz）。全链路规则：

- **生成**：`createPerson` 默认 `verified:false`，超管可传 `verified:true` 直接创建已验证账户；`personToRow` 据此写入云端 `email_verified` 时间戳。
- **存储**：`markEmailVerified` 本地先行落盘（本地可用不依赖云端），再异步双写云端；`updatePerson({verified})` 供超管随时修正或撤销验证状态。
- **传递**：`publicUser` / `personFromRow` 双向携带 `verified` 与 `emailVerifiedAt`，会话切换、云端重载后状态不丢失；验证成功时同步刷新当前会话工作副本与会话快照，避免"users 已验证、顶栏仍显示未验证"。
- **展示**：后台人员表的「验证状态」列、账户安全弹窗的验证日期均读取上述字段；后台表单可直接设置验证状态。
- **策略开关**：`emailVerifyOnce`（默认 true）决定是否强制未验证账户走绑定向导；设为 false 时不强制，管理员分配的账号凭口令即可使用。

> 排查记录：曾出现"新建账户验证状态不可用"——根因是云端 `personToRow` 未写 `email_verified`、`markEmailVerified` 只改本地、且后台无验证状态入口，导致云端重载后状态回退为未验证且无法修正。现已按上述全链路修复，并新增 5 项冒烟测试覆盖字段映射、创建/编辑、落盘与会话同步。

### 通讯录与自定义用户同步

- **权威数据源**：后台人员表（`state.users` / 云端 `personnel`）为唯一权威；通讯录成员列表由同步接口实时重建。人员新增、编辑、删除（含账户清理）后自动同步；通讯录不会复活已删除成员。
- **匹配优先级**：唯一标识（`id` / `owner_id` / `uid`） → 手机号指纹（兼容完整号码与前 3 后 4 脱敏号码） → 邮箱（忽略大小写）。
- **去重规则**：命中同一身份即合并，保留 `updated_at` / `created_at` 较新的记录；冲突写入 `conflicts`，通讯录页面顶部给出简要提示，不阻断展示。
- **字段兼容**：性别、年龄、个人签名与部门 / 身份为空时显示占位文案；学生之外隐藏年级字段。部门 / 身份改为下拉选择，内置选项含「学生家长」，历史自由文本自动保留。

### 在线状态同步

在线状态 `presence` 取 `online / away / offline` 三态，作为人员标准字段保存在本地用户表与云端 `personnel.presence` 列，人员新建 / 编辑时可在后台表单设置。展示与统计按**全站唯一口径**计算：

1. 停用账户（`status=disabled`）强制显示离线；
2. 当前登录会话中的账户始终显示在线（会话在线不写回存储，退出后自动回落到字段值）；
3. 其余账户按持久化的 `presence` 字段显示。

通讯录头像状态点、聊天头部、个人简介、后台「实时监测 → 当前在线用户」四处共用该口径；在线状态字段缺失或历史非法值统一回落离线，兼容旧数据。实时监测 `getRealtimeStats()` 返回 `onlineNow` 与 `onlineIds`。多账户同时在线时，每个会话的在线状态独立维护（在线 / 离开互不影响），通讯录与实时在线数会合并所有在线会话。

### 多账户同时在线与会话管理

同一浏览器可同时登录多个账户并随时切换，入口在顶栏的「切换账户」按钮（在线账户数角标）。行为规则：

- **登录去重**：以唯一标识（`uid` → 邮箱 → `id`）为会话键；同一账户重复登录只刷新资料并切换，不重复建会话；最多同时 8 个在线账户。
- **会话隔离**：每个会话独立保存账户资料、角色、当前视图、资料筛选、「已添加学习」清单、通讯录筛选 / 当前会话、站内消息与通知。切换账户时先快照旧会话再装载目标会话，互不干扰；共享的账户名单 / 角色权限 / 学习资料 / 感悟为平台级数据。
- **权限校验**：切换后按人员表最新角色重算权限；当前视图若被取消访问会自动回退到有权限的首个视图；管理后台仍仅超管可见。
- **独立在线状态**：每个会话可单独切换「在线 / 离开」；通讯录圆点、聊天头部与实时在线数合并所有在线会话计算。
- **退出行为**：「退出当前账户」只关闭当前会话，若还有其它账户则自动切到最近活动的一个；「退出全部账户」清空所有会话并回到登录页。
- **会话有效期与免登录**：每个会话携带 `issuedAt / expiresAt`（默认 7 天，可在 `config.js` 的 `auth.sessionTtlDays` 调整），登录 / 切换会滑动续期；过期会话在启动时自动清理。会话清单存 `localStorage`（跨标签共享），当前激活账户指针存 `sessionStorage`（每标签独立）：因此新标签页 / 新链接在有效期内直接恢复登录，不同标签可各自显示不同账户、互不覆盖。其它标签的发布 / 评论通过 `storage` 事件实时同步到本标签。
- **异常冲突**：账户被禁用或删除后，其会话在切换 / 启动时自动失效并清理；云端 SDK 同时只能持有一个账户的认证凭证，切换到非凭证持有者的云端账户会标记「云端待验证」，此时仅展示本地快照、不以其身份写云端，需用该账户重新登录后再同步。

接口层（`window.SunnyAPI`）：`upsertSession` / `listSessions` / `switchSession` / `setSessionPresence` / `closeSession` / `closeAllSessions` / `reconcileSessions` / `adoptCurrentSession` / `refreshSessionsFromShared` / `sessionTtlMs` / `isSessionExpired`；旧版本单账户登录态在启动时自动迁移为首个会话。

### 闲置超时二次验证（30 分钟）

- 登录后 **30 分钟无任何操作**（配置 `APP_CONFIG.auth.idleTimeoutMinutes`，默认 30），系统自动锁定当前会话并弹出独立的二次验证层。
- 验证页只需输入**当前账户的登录密码**，校验通过即原地恢复，不重新走登录向导、不清空任何数据与工作区；也可选择「退出当前账户」。
- 任意鼠标/键盘/触摸/滚动操作都会刷新闲置计时（节流落盘）；本地账户用统一口令校验，云端账户在必要时用云端密码登录做二次确认。
- 纯函数在 `js/api.js`（`idleTimeoutMs` / `sessionIdleMs` / `isSessionIdleLocked` / `stampActivity` / `formatIdleCountdown`）；计时与弹窗在 `js/app.js` 的「闲置超时二次验证」模块与 `css/styles.css` 第 14 节 `.reauth-*`。

### 跨设备同步（手机 / 电脑一致）

- 云端登录后，通过 `user_sync` 表在三个域同步：`workspace`（筛选、学习清单、会话消息、通知、表情等私有工作区）、`account`（账户资料 + 角色 + 权限矩阵 + 视图门禁）、`schedule`（课程表）。
- 本地变更节流上传（1.2 秒防抖）；启动与定时轮询拉取；以 `updatedAt` 较新一方胜出，拉取后仅落本地、不回推，避免回声循环。
- 效果：手机端新建/修改的资料、感悟、通知、权限分配与课程表，电脑端登录同一云端账户后自动一致；反之亦然。
- 实现：`js/api.js` 的 `buildUserSyncPayload` / `pushUserSync` / `pullUserSync` / `shouldApplySync`；`js/app.js` 的 `pullAllSync` / `pushSyncScope` / `scheduleSyncPush`。

### 课程表与班级主任

- **课程表界面**：侧栏「课程表」进入，顶部选择班级；表格按周一至周五 × 第 1–7 节展示课程、上课时间、当科老师、备注。内置全国小学通用作息模板（08:00–16:20），可由班级主任逐格覆盖。
- **班级主任**：新增内置角色「班级主任」（`r_headteacher`，含 `manage_schedule` 权限）。超管在「管理后台 → 人员管理」新建/编辑账户时选择该角色，并在「管理班级」多选框中勾选其负责的班级（1–6 年级 × 1–3 班，可多选，即一人可管多班）。
- **权限边界**：超管可编辑全部班级；班级主任仅能编辑其 `managed_classes` 内班级的课程表；普通教师/学生/家长仅可查看。前端 `canManageClass` 与数据库 `can_manage_class(class_key)` 双重校验。
- **云端落地**：`class_schedules` 表按节次存行，全员可读，写权限由 RLS 按班级主任/超管控制；本地演示模式改动落在浏览器存储。
- **打印 / PDF**：课程表右上角「打印 / PDF」按钮（所有可查看者可用）会生成一个独立的 A4 横向打印页，含班级、打印日期、上课时间、课程、当科老师与备注；通过隐藏 iframe 调起浏览器打印，在打印对话框中选择「另存为 PDF」即可导出，也可直接连接打印机打印。打印页为自包含 HTML（内联样式），不依赖站点 CSS；内容做 HTML 转义，无数据时同样以内置模板兜底。

### 账户清理（仅保留 admin）

管理后台 → 人员管理 底部「危险操作 · 账户清理」提供一次性清理能力：

1. **预检**：校验被保护的 admin 账户存在、启用、角色为 `admin`，且当前登录者就是该账户；若未找到、存在多个候选或角色不符，直接终止，不删除任何数据。
2. **第一步确认**：展示待删除账户清单、每个账户的关联数据数量和总体影响范围。
3. **第二步确认**：必须勾选确认框并输入配置中的短语（默认 `仅保留ADMIN`，见 `js/config.js` → `auth.accountCleanup.confirmPhrase`），两步缺一不可。
4. **清理范围**：删除其余账户的人员 / 资料记录、学习感悟、点赞记录、关联资料、站内会话，并从他人感悟中移除已删账户的点赞引用。admin 账户的身份键在所有删除路径中均被排除。
5. **孤儿身份**：账户表中已不存在、但仍散落在 `shares` / `profiles` / `share_likes` / `materials` 的旧 `owner_id`（例如历史种子数据）也会被纳入清理，避免残留无账户却仍占有数据的身份。
6. **结果报告**：返回已删除账户、孤儿身份、各类数据清理数量、失败项（逐项失败不中断其余账户）以及最终账户状态。

云端模式需要超管具备跨账户删除关联数据的 RLS 权限；本项目已为 `profiles`、`shares`、`share_likes` 增加 `*_delete_admin` 策略，并为 `shares` 增加 `shares_update_admin` 策略。注意：云端认证账户记录不由此接口删除；账号移出 `personnel` 白名单后即无法登录。

## 六、数据存储与重置

**云端模式**：用户资料与学习感悟保存在云端数据库，登录态由云服务维护，不在 localStorage 存储业务数据。**演示模式**：交互数据（用户、感悟、消息、通知、权限配置、登录态）保存在浏览器 `localStorage`，存储键为 `sunny-classroom-web-v1`（见 `js/config.js`）。

### 恢复初始演示数据

在浏览器中执行以下任一方式：

1. 打开开发者工具（F12）→ Console，执行：
   ```js
   localStorage.removeItem('sunny-classroom-web-v1');
   location.reload();
   ```
2. 浏览器设置 → 清除该站点（127.0.0.1:5173）的 Cookie 与网站数据。

### 首次加载有旧数据导致异常？

本项目已对持久化数据做了结构校验与字段兜底；若仍遇到异常，按上面方式清除一次即可。

## 七、常见问题排查（FAQ）

| 问题 | 可能原因 | 解决办法 |
|------|----------|----------|
| 终端提示端口被占用 | 5173 已被其他程序使用 | 换端口：`PORT=5174 npm start`，浏览器访问新端口 |
| 浏览器显示「无法访问此网站」 | 服务未启动 / 地址写错 | 确认终端显示启动成功；地址必须是 `http://127.0.0.1:5173`，不要写成文件资源管理器路径 |
| 页面样式错乱 / 图标不显示 | 通过 `file://` 打开或用旧缓存 | 用 `npm start` 启动并在 HTTP 地址访问；强制刷新 `Ctrl+F5` |
| 修改代码后页面没变化 | 浏览器缓存 | 服务器已设置 `Cache-Control: no-cache`，仍异常可 `Ctrl+F5` 强制刷新 |
| 刷新后登录态丢失 | 未勾选「记住登录状态」，或清除过站点数据 | 登录时勾选该选项；如需长期保持请勿清除站点数据 |
| 发消息后对方没回复 | 已切换到其他视图 | 模拟回复仅在停留在通讯录视图时触发，1.4 秒后出现 |
| 管理后台看不到 | 当前账号不是超管（正常安全设计） | 用超管账号登录；或由超管在「人员管理」把该账号角色改为超级管理员（普通用户无法自行切换/提权） |
| 某功能入口不见了 | 超管取消了对应视图门禁权限 | 联系超管在「角色权限 → 视图访问控制」检查该视图所需权限，或在「角色权限分配」为你的角色勾选该权限 |
| `node` 命令不识别 | Node.js 未安装或未加入 PATH | 重新安装 Node.js LTS 并重启终端 |

## 八、安全与合规说明

- **云端模式**：账号密码登录由 WorkBuddy 云服务提供，数据库通过行级安全（RLS）隔离——登录用户可读公共内容，但只能增改自己的资料、感悟与评论。前端仅持有可公开的 `endpoint` 与 `publishableKey`，底层环境与密钥由平台在服务端保管。邮箱验证码**仅用于忘记密码时验证身份**，会真实发送到你填写的邮箱，请勿用于测试无关邮箱。
- **演示模式**：登录为模拟校验、数据存于本机 `localStorage`，仅用于功能演示，**请勿存放真实个人信息**。
- 本地服务器已内置基础安全响应头（`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`）、路径遍历防护、隐藏文件访问拦截。
- 云端登录的 OAuth 回调要求发布的 HTTPS 域名，需在正式域名下使用；数据面始终通过平台分配的 `endpoint` 访问。
